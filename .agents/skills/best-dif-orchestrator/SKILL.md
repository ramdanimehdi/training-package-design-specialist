# منسق تصميم الحقائب التدريبية
استخدم هذه المهارة لكل طلب حقيبة تدريبية كاملة أو تصميم دورة من البداية للنهاية.
## ترتيب إلزامي
1. استخلص الموضوع، الفئة، المستوى الحالي، نتائج الأداء، الوقت، البيئة والقيود. اسأل سؤالاً مركّزاً إذا افتقدت معلومة محورية؛ وإلا اذكر الافتراضات ولا تتظاهر باليقين.
2. حدّد BEST: Basic / Elevated / Specialist / Trainer-Consultant مع سبب وأثره على العمق.
3. صغ أهدافاً سلوكية قابلة للملاحظة، وصنّف كل هدف K → KS → SK → S1 → S2 → A.
4. حلّل كل هدف على حدة وفق DIF: الصعوبة، أهمية الدقة المعيارية، التكرار؛ اكتب المبررات.
5. بعد DIF فقط، حدّد مستوى ممارسة DBA المناسب D1/D2/B1/B2/A1/A2. هذه رموز **حجم الممارسة** ولا تساوي تلقائياً سُلّم التمكن.
6. اصنع تسلسلاً تراكمياً للتعلم D1 → D2 → B1 → B2 → S1 → S2 → A إلى نقطة وصول الهدف، ولا تقفز على المتطلبات. S1 هو النشاط الذي تم اختباره في B2 مع إضافة معايير جودة صريحة.
7. حدد طريقة التدريب انطلاقاً من الهدف، التمكن، طبيعة الأداء وحجم الممارسة، لا من عنصر التشويق وحده.
8. لكل عنصر Review Test مناسب؛ وفي النهاية Criterion Test على الأداء المستهدف.
9. أنشئ أربعة مخرجات لكل عنصر: مذكرة متدرب، شرائح، أداة تدريبية، مرشد مدرب.
10. افحص التوافق بين جميع المخرجات باستخدام quality-audit.
## قواعد
لا تبدأ بصناعة المحتوى التفصيلي قبل مصفوفة التصميم. لا تعرض تصنيفات مؤكدة عند غياب أدلة؛ صنّفها «افتراض أولي».
لا تتصل بخدمات API أو مواقع خارجية أو تستخدم نماذج سحابية عبر كود. العمل في نطاق الأداة التي تشغّل المهارات.
استخدم references/design-matrix.md في كل حقيبة.


## قاعدة مشتركة إلزامية
عند التنفيذ داخل مشروع أخصائي تصميم الحقيبة التدريبية، راجع سياسة المصادر في `../training-package-design-specialist/references/source-policy.md` قبل إضافة أي ادعاء تخصصي؛ استخدم فقط مراجع مشروع المستخدم، ووثّق الصفحات/الأقسام إن توفرت، ووسم الافتراضات والأمثلة الافتراضية. لا تملأ النقص بالمعلومات المختلقة، ولا تستخدم API أو بحثاً خارجياً تلقائياً. يبدأ منسّق `training-package-design-specialist` التحليل ويرتب المخرجات.
