# أخصائي تصميم الحقيبة التدريبية

**Training Package Design Specialist**

تصميم **Mehdi Ramdani — [@ramdanimehdi](https://github.com/ramdanimehdi)**.

مجموعة من **14 مهارة Agent Skills** لتوجيه تصميم الحقائب التدريبية وفق **BEST-DIF Mastery Model ومربع التمكن**. تبدأ من مراجع المستخدم وفجوة الأداء، ثم تربط الأهداف والممارسة والأنشطة والتقييم بالمخرجات. وظيفتها توجيه التصميم منهجياً، مع منع اختلاق الحقائق والمراجع.

## مراجع كل دورة تأتي منك

أنشئ **مشروعاً مستقلاً لكل دورة**، وأضف كتبها ومقالاتها وأدلتها وإجراءاتها ومعاييرها والمواد التوجيهية التي تملك حق استخدامها. في الواجهات الحوارية، ارفعها إلى المشروع أو المحادثة؛ في البيئات المحلية نظّمها مثلاً هكذا:

```text
my-training-project/
  brief/          وصف الجمهور والفجوة والمدة والقيود
  references/     مصادر موضوع هذه الدورة فقط
  output/         مصفوفة التصميم ومخرجات الحقيبة
```

هذه أسماء تنظيمية مقترحة. احتفظ بالمراجع والمخرجات في مشروعك الخاص، ولا ترفعها إلى مستودع التوزيع العام.

تفهرس المهارة المصادر وتربط الادعاءات التخصصية بمصدر وصفحة أو قسم إن أمكن. تفصل **[مستند إلى مرجع]** و**[استنتاج تصميمي]** و**[افتراض معلن]** و**[نقص مرجعي]**. عند نقص الأدلة تقدم قائمة بالنواقص ومصفوفة أولية موسومة، وتوقف كتابة المحتوى العلمي غير المسند. لا تختلق مراجع أو صفحات، ولا تجلب مصادر من الإنترنت تلقائياً.

## المنهج والمخرجات

1. **BEST:** تحديد المستوى Basic / Elevated / Specialist / Trainer/Consultant.
2. **KSA:** صياغة أهداف قابلة للملاحظة وتصنيفها: `K → KS → SK → S1 → S2 → A`.
3. **DIF:** تحليل Difficulty وImportance وFrequency لكل هدف مع المبررات.
4. **DBA:** اختيار حجم الممارسة بعد DIF فقط: `D1 / D2 / B1 / B2 / A1 / A2`. لا تُخترع معادلة عددية غير موثقة.
5. **رحلة التمكن:** `D1 → D2 → B1 → B2 → S1 → S2 → A` حتى نقطة الوصول؛ دون تجاوز المتطلبات السابقة. يعيد S1 مهمة B2 بمعايير جودة صريحة.
6. اختيار الأسلوب بناءً على الهدف والتمكن وحجم الممارسة وطبيعة المهمة.
7. **Review Test** بعد كل عنصر، و**Criterion Test** في النهاية؛ تقييم عملي وسلوكي عندما يتطلب الهدف ذلك.
8. تدقيق الاتساق والمصادر بين الأهداف والممارسة والتقييم والمخرجات.

**KSA تصنيف للأهداف، وDBA حجم للممارسة، ورحلة التمكن تسلسل للتعلم.** تشابه الرموز لا يجعلها سُلماً واحداً؛ لا تُستبدل S1/S2 بـA1/A2. إذا لم تكفِ المدة، يُقترح تعديل النطاق أو المدة بدلاً من تخفيض الممارسة المطلوبة دون مبرر DIF.

| المخرج لكل عنصر | التفاصيل |
|---|---|
| مذكرة المتدرب | شرح وخطوات وأمثلة وأخطاء شائعة وتطبيقات مرتبطة بالمراجع |
| شرائح العرض | فكرة رئيسية لكل شريحة، النص الفعلي، ومواصفات تصميم قابلة للتحرير |
| الأداة التدريبية | نشاط أو ورقة عمل، التنفيذ والناتج وآلية القياس |
| مرشد المدرب | ما يقوله ويفعله، الأسئلة، الوقت، متابعة التنفيذ، إدارة القاعة واستخلاص التعلم |

ترتبط جميعها بالأهداف ومعايير القبول نفسها. تفصل الحلول عن أوراق المشاركين. مواصفات العربية: **RTL، خط Simplified Arabic، أرقام 123**؛ أوراق A4 وشرائح 16:9 افتراضياً. لا يُضمّن ملف الخط؛ توفره يعتمد على أداة التصميم والجهاز.

## التثبيت في Claude

### واجهة Claude التي تدعم رفع المهارات

1. نزّل [training-package-design-specialist-claude.zip](dist/training-package-design-specialist-claude.zip). لا ترفع أرشيف المستودع الكامل كمهارة واحدة.
2. افتح `Customize → Skills`، ثم `+ → Create skill → Upload a skill` حسب الواجهة المتاحة. قد يلزم تفعيل Code execution and file creation وسياسة مؤسستك.
3. ارفع ZIP وفعّله. يحتوي على مجلد واحد في أعلاه `SKILL.md` والمراجع والوحدات المدمجة والترخيص؛ لا يعتمد على مهارات مجاورة.
4. أنشئ مشروع الدورة وأضف مراجعها، ثم استخدم أمر البدء أدناه.

راجع [تعليمات Claude الرسمية](https://support.claude.com/en/articles/12512180-use-skills-in-claude) عند تغير القوائم. لم يُجرَ اختبار رفع فعلي إلى حساب Claude ضمن هذا الإصدار.

### Claude Code

انسخ مجلد المهارة من `.claude/skills/` في المستودع إلى `.claude/skills/` داخل مشروع دورتك. انسخ `CLAUDE.md` إلى الجذر أو ادمج التعليمات ذات الصلة دون استبدال تعليماتك الحالية. افتح الجلسة واستدعِ:

```text
/training-package-design-specialist
```

هذه نسخة موحدة تضم الوحدات المتخصصة الـ13 كمراجع داخلية؛ لا يلزم نسخ `.agents` معها. المرجع: [Claude Code Skills](https://code.claude.com/docs/en/skills).

## التثبيت في Codex وبيئات Agent Skills

1. نزّل التوزيعة الكاملة أو استنسخ المستودع:

```bash
git clone https://github.com/ramdanimehdi/training-package-design-specialist.git
```

2. انسخ محتويات `.agents/skills/` كاملة إلى `.agents/skills/` في مشروع دورتك. حافظ على المجلدات المخفية والعلاقات النسبية؛ المهارات الفرعية تقرأ سياسة المصادر من الرئيسية.
3. ادمج `AGENTS.md` في الجذر دون محو تعليماتك الحالية. افتح المشروع في مضيف يدعم المسار، واستدعِ `$training-package-design-specialist` أو اطلب المهارة باسمها.
4. للمضيفات الأخرى اتبع مسارها الموثّق؛ معيار `SKILL.md` لا يفرض مسار اكتشاف واحداً لجميع المنتجات.

مراجع البنية: [Agent Skills Specification](https://agentskills.io/specification) و[تعليمات OpenAI الرسمية](https://learn.chatgpt.com/docs/build-skills).

### ChatGPT وChatGPT Projects

إذا توفر مستورد Skills مخصصة، استخدمه وفق متطلبات الواجهة. رابط GitHub وحده لا يضمن تثبيتاً تلقائياً. عند غياب الميزة، فك ZIP المفرد وأرفق `SKILL.md` وموارده إلى مشروع ChatGPT بالطريقة التي تسمح بها الواجهة، واطلب قراءة التعليمات قبل التصميم. هذه طريقة يدوية مقيدة بقدرة المضيف وسعة الملفات؛ لا نضمن استيراد ZIP في كل حساب. لا تحتاج إعداد API خاص بهذه الحزمة.

## أول تشغيل وأمثلة

تقدم المهارة نفسها عند **أول استدعاء معلوم في المشروع أو المحادثة عندما تسمح البيئة بذلك**، مع نسبة التصميم إلى Mehdi Ramdani وتوضيح دور مراجع المستخدم. لا تزعم وجود رسالة تثبيت تلقائية أو ذاكرة مشتركة دائمة بين المنصات.

```text
استخدم أخصائي تصميم الحقيبة التدريبية. هذه مراجع دورتي المرفقة.
الجمهور: [...]. الأداء المطلوب: [...]. المدة والبيئة: [...].
ابدأ بفهرس المصادر وفجواتها ثم مصفوفة BEST وKSA وDIF ثم DBA ورحلة التمكن.
لا تكتب محتوى تخصصياً بلا مصدر. بعد المصفوفة صمم المخرجات الأربعة لكل عنصر.
```

- «راجع DIF لكل هدف قبل اقتراح DBA؛ افصل المصادر عن القرارات التصميمية.»
- «راجع انتقال B2 إلى S1 واقترح قائمة تحقق معلنة إن لم يتضمن المرجع معيار أداء.»
- «دقق الاختبار النهائي: هل يقيس الأداء العملي أم الحفظ فقط؟»

راجع [أمر البدء](examples/starter-request.md) و[سيناريوهات التحقق](examples/acceptance-scenarios.md).
